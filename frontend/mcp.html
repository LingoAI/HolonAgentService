ParameterChecks
transactionHash · requiredReceipt, execution status, block inclusion and observed confirmations on X Layer mainnet.
expectedPaymentExact ERC-20 event: token, sender, recipient and amountRaw. Supply all four; the amount is in base units.
allowanceExplicit token, owner and spender. Returns allowance at the end of the transaction block and current snapshot block; unavailable values remain unknown.
contractAddressExpected transaction recipient. Third-party business state is not inferred from generic logs.
jobIdEvent binding and current job state in the Holon mainnet canary escrow.
manifestCidHolon manifest and referenced document bytes, SHA-256, size and CID integrity. Supports CIDv1 raw SHA-256 blocks, up to 8 KiB for the manifest and 16 KiB for the document.
expectedDigestExpected Keccak-256 of manifest bytes; requires manifestCid. With jobId, the onchain deliverable digest is also checked.

Read the result
Inspect status (PASS, WARNING or FAIL), warnings, verificationStatus, verified, and each entry in checks. A completed HTTP request can return mismatch or not_found; neither is successful verification. Upstream outages return an error.
interpretation contains the AI summary, findings with evidence references, suggested next checks and limitations. deterministicInterpretation preserves the code-generated conclusion. AI text is advisory: it never changes the verdict, transaction facts or checks. Only structured public evidence is sent to the model; delivery document text and payment credentials are excluded. If the required AI explanation is unavailable, no new payment is settled.

      
Confirmations are observations, not a finality guarantee. Token logs do not establish an arbitrary token's economic value. File integrity checks establish byte consistency, not authorship or content quality. Without a job ID or trusted expected digest, IPFS integrity is checked independently of the transaction.

      
For the complete input schema and supported escrow address, open capabilities. Existing A2A report delivery is available through ASP #13847. No private-key custody or fund operations in the verifier. Not investment advice or a security audit.
